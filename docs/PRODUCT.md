# RustDesk macOS 伴侣应用需求

本文定义 `decouple-rustdesk` 分支的目标和验收条件，正式应用名待定。范围依据 [项目交接说明](../AGENT_HANDOFF.md) 第 5–9 节。当前基线 `df365a4` 仍由 `AppController` 接入 `UUSensor`，下列里程碑均待验收。模块改动、状态转移和恢复顺序见[技术设计](rustdesk-technical-design.md)。

## 用户与使用流程

用户通过自建 RustDesk 从手机、平板或另一台电脑操作自己的 Mac。伴侣应用运行在被控 Mac（macOS 14+），负责适配屏幕比例、窗口、字号和输入。连接、认证、中继和加密继续由 RustDesk 与用户的 hbbs/hbbr 负责。第一阶段无需改动 RustDesk 客户端或服务器，无需向伴侣应用提供远控密码。

以手机竖屏编辑文档为首个完整场景：

1. 在 Mac 上选择手机型号与竖屏配置。应用说明辅助功能和录屏权限各用于哪些操作，权限不足时显示受影响的功能和授权入口。
2. 启用虚拟屏，从手机通过自建 RustDesk 连入，在 RustDesk 的显示器列表中手动切到该屏。需要从主屏开始时，用户可选择将虚拟屏设为主屏。
3. 将文档窗口移入并铺满，调整字号，用单指滚动、长按打开右键菜单、长按拖动选择文字。使用普通显示器时保留原有输入行为。
4. 断开后回到 Mac，窗口回到原显示器与位置，字号恢复到操作前的值。若本次更改了主屏，也要恢复原主屏。

## 交付范围与验收

| 优先级 | 要交付的行为 | 通过条件 |

| P1 / M0 手机竖屏 | 单手机竖屏、连接感知、手动切屏、三种手势、窗口铺满、字号调整和正常断开还原。 | 用真实手机经自建服务完成下节全部 M0 用例。自动感知和手势降级分别记录，不能用手动操作替代相应通过结果。 |
| P2 / M1 多屏与恢复 | 提供手机竖屏、手机横屏、平板和电脑四档，以及机型库、App 资源库、跨屏搬运和按 App 记忆字号。按实际控制端界面验证工具栏避让。 | 四档分别建屏并从客户端切入，检查比例、清晰度及工具栏遮挡。从资源库打开 App、跨屏搬运并恢复窗口，重新使用同一 App 时应用已记忆的字号。已有虚拟屏时保留其归属；资源不足时明确提示。强制退出伴侣应用后重启，核对布局与字号恢复。 |

## M0 真机验收用例

测试前记录 macOS、RustDesk 两端版本、手机型号与输入模式，保存原主屏、测试窗口所在屏幕及位置、窗口大小和字号。选用支持字号调节且能滚动、选字的文档窗口。

| 操作 | 预期结果 |
|---|---|
| 启动 RustDesk 服务但不连入，再由手机连入、断开并重连 | 空闲进程不会触发会话。真实连接与断开各触发一次相应状态变化；重连后再次可用。信号不可用时说明原因，允许用户手动开始或结束。 |
| 开启竖屏并在手机端切入，将窗口移入、铺满并放大字号 | 客户端可选中比例与配置相符的屏；文档可读，窗口占满可用区域。 |
| 单指滑动后抬手、静止长按、长按后拖过文字 | 文档惯性滚动后停下；静止长按只打开一次上下文菜单；拖动能选中文字。分别记录触摸和虚拟鼠标模式的结果，注明支持的模式。 |
| 切回普通显示器操作，再切回虚拟屏 | 普通显示器操作保持 RustDesk 原有语义，切回后在支持模式下重新获得手势。若无法可靠区分输入来源或目标屏，停用改写并说明限制，保留建屏和窗口能力。 |
| 正常断开，与测试前记录对照 | 已搬窗口的显示器、位置、尺寸和字号均恢复，临时主屏设置恢复；再次连接时可重复以上流程。 |
| 分别撤销辅助功能或录屏权限，按提示重新授权 | 指明缺少哪项权限及受影响操作，仍可使用其余可用功能；重新授权后按提示恢复。 |

## 待验证与决策

- **连接信号**：在空闲、连入、断开、重连时比对进程状态、IPC/socket 或日志，选能区分活动会话的信号。并发连接时单独验证一个控制端退出会否误触发还原；确认前不承诺多会话支持。
- **输入路径**：验证 `TouchTap` 能否收到并区分 RustDesk 的输入事件，检查是否与客户端原生手势重复。若验证失败，M0 记录为部分通过，交付范围标明“虚拟屏、窗口与字号”。
- **显示能力**：在目标 macOS 与客户端版本上检查显示器枚举、已有虚拟屏共存、手动切换和临时设主屏的效果。屏数上限和连入时默认显示哪块屏均以实测为准。
- **应用身份与界面**：正式名称、签名身份及设置界面的复用范围待定。自建服务器地址与公钥配置入口为可选项，M0 沿用用户在 RustDesk 中已有的配置，保留固定公钥和加密路径。

## Brand Personality

原生、克制、可靠。看上去就是苹果自己做的系统工具，像「系统设置」「访达」那样，不像第三方插件。文字短、书面、冷静，一个状态一句话说清楚（「等待连接」「手机屏已就绪」），不用口语、不加感叹。

## Anti-references

- 自带一套视觉语言的第三方工具：自定义配色、渐变按钮、玻璃卡片、花哨的品牌色
- 把所有设置从上往下一项项平铺的长页面，内容不分层
- 自己画的图标、和系统不一致的控件
- 为了显得有设计感而加的装饰动画

## Design Principles

1. **像系统自带的一样**：控件、图标（只用 SF Symbols）、颜色都用苹果的系统语义；Mac 端按 macOS 的规矩，虚拟屏上的面板按 iOS 的规矩
2. **背后复杂、用户无感**：默认状态保留 RustDesk 原有操作；装好之后什么都不用管，要用的人自己打开选项
3. **每个状态都讲清楚**：空的、加载中、出错都一眼看懂，出错写明哪个 App、出了什么事、接下来怎么办
4. **内容分层**：天天看的放菜单栏，偶尔改的放设置，只管某一块屏的设置放在那块屏的详情里
5. **一处定义，到处一致**：字号、颜色、间距、圆角都从设计令牌取，不在各处写死数字

## Accessibility & Inclusion

- 文字对比度达到 WCAG 2.2 AA（普通文字 4.5:1，大字和图标 3:1），浅色、深色都要达标
- 跟随系统的深色模式、提高对比度、减弱动态效果
- 触屏上的可点区域不小于 iOS 的 44 点（在手机屏上折算后约 56 点）
- 状态不只靠颜色表达，配文字或图标
